## 3. Функциональность, которая НЕ тестировалась (и обоснование)

В рамках данной итерации проекта осознанно **не подвергались глубокому тестированию** следующие аспекты:
1. **Интеграция с реальными платежными системами (эквайринг):** 
   - *Обоснование:* В текущей бизнес-логике проекта оплата заказов происходит оффлайн (при получении в пункте выдачи или курьеру), поэтому код обработки онлайн-платежей в приложении отсутствует и не требует тестового покрытия.
2. **Нагрузочное тестирование всех страниц информационного модуля (`pages`):** 
   - *Обоснование:* Страницы «О нас», «Вакансии», «Контакты» являются статическими (с минимальной нагрузкой на БД). Нагрузочное тестирование (Locust) было сфокусировано исключительно на критическом пути системы: главная страница каталога, поиск и оформление заказа.
3. **Кросс-платформенное тестирование на физических мобильных устройствах:** 
   - *Обоснование:* Проверка адаптивности выполнялась с помощью программной эмуляции устройств в Google Chrome DevTools и симуляторов, физическое тестирование на парке реальных смартфонов/планшетов не проводилось из-за ограничений тестовой среды.

## 4. Зоны с высоким риском и требования с наибольшим количеством дефектов

На основе анализа журнала дефектов (`ISSUES.md`) и сложности бизнес-логики были выделены зоны повышенного риска:

1. **Модуль управления заказами и складскими резервами (Требования ФР-7, ФР-8, ФР-11, ФР-14):**
   - *Уровень риска:* **Высокий**.
   - *Причины:* Именно в этом модуле было выявлено наибольшее количество потенциальных краевых случаев (Edge Cases) на этапе верификации. Сюда относятся ситуации с одновременным заказом последней книги на складе, корректным переключением статусов экземпляров (`a -> r -> s`), возвратом товара при отмене заказа и срабатыванием очереди ожидания (`Waitlist`). 
   - *Меры:* Данная зона покрыта наибольшим количеством интеграционных и сценарных E2E-тестов (`TestOrderProcess`, `test_order_full_state_lifecycle_scenario`).
2. **Интеграция с внешними сетевыми API (Требование ФР-16):**
   - *Уровень риска:* **Средний / Высокий**.
   - *Причины:* Зависимость от сторонних сервисов (Google Books, OpenWeatherMap). В случае сбоев сети или изменения структуры ответов API со стороны сторонних ресурсов приложение может столкнуться с тайм-аутами.
   - *Меры:* Для минимизации рисков написан специальный интеграционный тест с использованием заглушек (`@patch`), страхующий приложение от падений при недоступности интернета.
