# Отчет о нагрузочном и стрессовом тестировании

## 1. Цели и критерии
- **Цель:** Определение производительности приложения при имитации 50 одновременных пользователей и поиск точки деградации системы.
- **Критерии успеха:** Время отклика (Average Response Time) < 2000 мс, отсутствие ошибок (Failures = 0%).

## 2. Профиль нагрузки
- Имитируется поведение пользователей: 70% просмотр каталога, 20% поиск, 10% добавление в корзину.
- Использовался инструмент **Locust**.

## 3. Результаты тестирования

| Тип теста | Кол-во пользователей | Среднее время (ms) | Доля ошибок |
| :--- | :---: | :---: | :---: |
| **Базовый (эталон)** | 1 | ~400 | 0% |
| **Нагрузочный** | 50 | ~3470 | 0% |
| **Стрессовый** | 50 (стабильно) | ~10814 | 0% |

### Анализ графиков:
- **График "Number of Users":** Наблюдается резкий скачок нагрузки до 50 пользователей в 09:49.
- **График "Response Times":** Виден резкий рост времени отклика в момент подключения 50 пользователей (с 0 до 10-20 секунд). 
- **Точка деградации:** Приложение начинает деградировать (время отклика превышает 2 сек) при достижении ~10 пользователей.

## 4. Выявленные узкие места (Bottlenecks)
На основе данных тестирования выявлены следующие узкие места:
1. **Холодный старт (Cold Start):** Бесплатный тариф Render.com переводит приложение в сон, что вызывает задержки при первом обращении.
2. **Низкая производительность БД / Статики:** Высокое время отклика (Average ~3-10 секунд при 50 пользователях) указывает на то, что сервер не справляется с одновременной генерацией HTML-шаблонов и выполнением SQL-запросов под нагрузкой. 
3. **Отсутствие кеширования:** Тяжелые элементы (погода, календарь) запрашиваются при каждом обновлении страницы.

## 5. Выводы
Приложение успешно справляется с 1 пользователем, однако при нагрузке в 50 человек время отклика становится недопустимо высоким для комфортной работы. Для улучшения показателей рекомендуется:
1. Переход на платный тариф (предотвращение сна).
2. Реализация кеширования (Redis) для часто запрашиваемых данных.
3. Оптимизация SQL-запросов с использованием `prefetch_related` в Django.
