# Отчет по автоматизации UI-тестирования (Playwright)

В рамках выполнения Задания 4 (пункт 4) была проведена автоматизация пользовательских сценариев через интерфейс браузера.

---

## 1. Технологический стек
- **Язык и фреймворк:** Python 3 + `pytest`
- **Инструмент автоматизации:** **Playwright** (плагин `pytest-playwright`). Выбран за встроенную поддержку автоматических ожиданий (Auto-waiting), высокую скорость работы, надежность изоляции контекстов и отсутствие необходимости скачивать внешние веб-драйверы.

## 2. Реализация требований задания

### Паттерн Page Object
Логика взаимодействия со страницами строго отделена от самих тестов. Создан файл `page_objects.py`, в котором реализованы классы:
- `BasePage` — содержит базовый URL и метод навигации.
- `CatalogPage` — инкапсулирует локаторы и методы для главной страницы (поиск книг `search_for_book`, переключение темы `switch_theme`).
- `LoginPage` — инкапсулирует локаторы для формы авторизации.
*Тесты в файле `test_ui.py` только вызывают методы этих классов, не обращаясь к CSS-селекторам напрямую.*

### Независимость тестов и уникальные тестовые данные
Каждый тестовый сценарий полностью независим. Для проверки негативного сценария авторизации генерируются уникальные данные на лету с использованием текущего системного времени:
```python
unique_username = f"fakeuser_{int(time.time())}"
```

---

Это гарантирует, что тесты можно запускать параллельно, и они не будут конфликтовать в базе данных.
Использование явных ожиданий (Explicit Waits)
Вместо устаревших и нестабильных фиксированных пауз (`time.sleep())` используются встроенные явные ожидания `Playwright`.

**Конструкции вида:** `expect(catalog.book_cards.first).to_be_visible()`
заставляют фреймворк непрерывно опрашивать DOM-дерево. Как только элемент появляется на странице, тест мгновенно продолжается, что защищает тесты от "морганий" (flakiness) из-за задержек сети.


### Автоматическое сохранение скриншотов при падении
Для фиксации ошибок реализована кастомная связка "Хук + Фикстура" в pytest.
Хук `pytest_runtest_makereport` анализирует статус завершения теста.
Фикстура `auto_screenshot_on_failure` перехватывает этот статус, и если он равен failed, отдает браузеру команду page.screenshot(...).
Для демонстрации работоспособности этого механизма тест `test_login_invalid_user_ui` был намеренно спроектирован как падающий (введены несуществующие учетные данные). При прогоне система корректно зафиксировала ошибку и сохранила дамп экрана в папку `test-results/`.
